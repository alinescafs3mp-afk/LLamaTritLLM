# Real conversational acceptance, audit22

A successful compiler, test runner, declining teacher loss or six learned replies are NOT an adequate chatbot.
Always report known TRAIN recall separately from other formulations and the actual free-running dialogue.
Do not weaken the existing smoke/parity/cancellation/state/GUI/update tests to make an artifact green.

## Native sequence

1. All managed/real worker/headless tests and native self-tests on the build host. New DialogueBatchSelfTest exercises
   batch8/64, planned selection counts, exact RNG consumption, real parameter updates and optimizer resume.
2. Actual direct creation with course/context/transfer versus raw creation->restart->training must have the same stored
   data and updates under identical native settings. Current user workspaces are not test fixtures.
3. Actual Check conversation must produce all retained reports plus new full62case report, matching the committed
   revision/hash. Use original model-generated earlier replies. Check protected files and publication count unchanged.
4. Run --learning-lab --course --context-practice --transfer-practice --enforce-guard in a NEW isolated directory.
   State requested/completed steps, architecture, seed, batch, LR and device. A disclosed host pilot can be shorter;
   it must not be labelled a completed6000step course. Exit3 records a guard rejection, not successful completion.
5. Run full Windows GUI and genuine RTX5080CUDA learning on target before declaring that platform passed.
   CPU fallback is NOT GPU acceptance. Report full known/new/old-public-context answers including negative ones.

## Meaning of the new report

The62cases are public development data, not a hidden test. Exact target mismatch can reject an acceptable paraphrase.
Conversely, grammar without relevance is not a correct answer. Read the full text and separately note loops, wrong-topic
replies, invented unknown facts, identity confusion and context truncation. The old16paired tasks must stay frozen.

Recorded-training exclusion checks both reference and actually generated input histories against saved train rows and
up to256recent learned entries. It cannot prove absence in all historical/deleted/imported data. Do not advertise a new
name as globally unseen merely because it was omitted from the new synthetic grid. No evaluator targets reach gradients.

The author supplied independent Python A/B with the SAME v22data and initial seed, not a native run or a pure old-package
vs new-package comparison. Corrected final-corpus reports are canonical; earlier grammar-draft reports are historical.
No single-seed aggregate or count of written tests establishes general conversational fluency.
