# Audit15 performance and responsiveness acceptance

No actual C# timing, memory or GUI measurement is available in the authoring container.
All earlier benchmarks are retained. This pass primarily removes initial UI-control construction and repeated delivery bytes,
not training FLOPs. Do not relabel a smaller archive as a faster neural network or a passing loss as conversational quality.

1. Measure opening a250-exchange chat before/after with identical journal and model. Teaching controls should not exist until
   expansion; compare UI load time/managed allocations, verify reopening an expander preserves its typed correction.
2. Show/hide parameters repeatedly, change scale, switch tabs, append response text and scroll upward. No whole chat rebuild,
   draft loss, forced tail scroll or silent action completion. Measure frame responsiveness on target DPI, not static source.
3. Catalog scan only direct model children and bounded remembered paths, never loads all weights. Verify locked/broken entries
   remain distinguishable; opening a failed entry preserves active weights. Keep safe-preview temporary memory tradeoff.
4. Build-stage full publish is allowed for deterministic dependency enumeration. Measure the FINAL app-only update archive and
   inspect EVERY entry. Native CUDA/LibTorch/.NET/Avalonia files must be absent. The64MiB check is uncompressed owned payload,
   not a promised archive size. Both trainer binaries and every adjacent data copy must be present.
5. Check-Update deliberately hashes retained large libraries. Measure diagnostic time separately from launch/training; this is
   one validation operation, not a startup download. Missing/mismatched file = refusal, not automatic vendor replacement.
6. Run trained-device -> FP32 master -> packed disk -> CPU incremental parity after actual gradient updates. Exact file/in-memory
   quantization equality plus tolerant native CPU/CUDA logits. Deterministic generated round-trip text must match. This isolates
   serialization/inference errors but cannot prove data adequacy or language fluency.

Record .NET/OS/CPU/GPU/driver, model architecture, actual optimizer steps, sequence length/batch and dataset version. Preserve
all prior cpuPreparation/textPreparation/attentionAndJournal/initializationAndElementwise/packing/replay/neural measurements.
Retain raw reports; no minimum speed ratio and no invented benchmark results. Model diagnostics excludes raw chat and training
content but contains the model display name and technical settings; review before sharing.
