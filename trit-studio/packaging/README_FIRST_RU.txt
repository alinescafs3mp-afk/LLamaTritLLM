TRIT STUDIO · первый запуск

1. Распакуйте весь архив, не переносите отдельно EXE.
2. Windows: запустите Check-laptop.cmd. В diagnostics появится отчёт.
3. Запустите Start-TritStudio.cmd или TritStudio.exe.
4. На вкладке «Модель и обучение» по умолчанию выбран этап «Без обучения».
   Нажмите «Создать без обучения»: появится модель со случайными весами,
   с нулём шагов оптимизатора и выключенным автообучением.
5. Проверьте ответы. Затем отдельно запустите «Базовый претрейн»:
   используются только 48 коротких текстов pretrain.jsonl, не диалоги.
6. Снова проверьте те же вопросы в новом чате, затем выберите
   «Разговорный корпус» и нажмите кнопку дообучения. В нём 2474 учебных
   примера. При переходе с базового этапа прежние 48 текстов сохраняются.
7. Для сравнения этапов оставляйте автообучение выключенным, используйте
   одинаковые вопросы, новый чат, температуру 0 и один лимит ответа.
   Эталоны находятся в evolution внутри рабочей папки модели. Это файлы
   только для чата, а не полные копии оптимизатора для продолжения обучения.
   Кнопка «Открыть папку эталонов этапов» показывает их расположение.
8. Режим быстрого запуска с разговорным обучением остаётся доступен
   отдельно. Ни один режим не загружает готовый чужой предобученный мозг.

.NET уже входит в portable-папку. SDK, Python и Visual Studio не нужны.
Для нативных библиотек Windows может потребоваться Microsoft Visual C++
Redistributable x64. Для CUDA нужен совместимый NVIDIA-драйвер. Скрипты
не устанавливают драйверы и не требуют прав администратора.
CUDA Toolkit / nvcc не используются для сборки собственных CUDA-ядер.
Запуск GPU подтверждается реальным тестом, не наличием файла CUDA DLL.

Данные пользователя по умолчанию находятся в LocalApplicationData/TritStudio.
Точный путь виден в интерфейсе. Переменная TRITSTUDIO_HOME позволяет явно
выбрать другую доступную для записи папку до запуска. Не храните рабочие
данные внутри папки очередного обновления программы.

Если CUDA недоступна, приложение выбирает CPU-тренер и показывает причину.
Check-laptop.cmd при этом НЕ выдаёт CPU-результат за успешный GPU-тест.
Для намеренно CPU-only проверки: powershell -NoProfile -ExecutionPolicy
Bypass -File .\Check-laptop.ps1 -CpuOnly

Это конструктор экспериментальных микромоделей. В комплекте НЕТ уже
предобученной универсальной модели. 2474 разговорных учебных примера и 48 отдельных базовых текстов являются
стартовым материалом, а не гарантией свободного разговора на любую тему.
Архитектура, объём данных и результаты обучения определяют качество.
Контрольные validation.jsonl, test.jsonl и все challenge*.jsonl запрещены для обучения.

Приложение не устанавливается в систему и не запускает сетевой сервер.
Полный список приёмки: docs/LAPTOP_ACCEPTANCE_RU.md.

Аудит 3: доступен счётчик контекста до отправки и причины остановки ответа.
На вкладке обучения можно очистить ожидающие примеры, оставить 8 снимков
цепочки отката и переподключить тренер. Изменение весов не отменяется
очисткой очереди. После обслуживания автообучение включается явно.

Аудит 4: Check-laptop.cmd также сохранит изолированные CPU/CUDA-бенчмарки. Рабочие модели не изменяются.

Аудит 13: при повторной отправке отменённого исключённого запроса сохраняется
флажок «не обучать», если не написан новый черновик. История читается в пределах
зафиксированного хвоста; пропущенные повреждённые записи не удаляются.

Аудит 14: повреждённая новая рабочая папка отклоняется до разборки прежней
сессии. Видно, что идёт проверка, и остаётся прежний чат при отказе.
Проверка ноутбука дополнена измерениями первого копирования весов и
CPU-нормализации; результаты не объявляются ускорением без замеров.
