# LLamaTritLLM — Тернарная (в стиле BitNet 1.58) Llama на чистом C#

[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE.txt)

**LLamaTritLLM** — реализация LLM **в стиле BitNet 1.58-bit** на **C#** с нуля,
на **архитектуре Llama** — обучение **только на CPU**, без внешних ML-фреймворков,
без GPU, без CUDA, без Python.

Каждый **обучаемый параметр** (таблица эмбеддингов, проекции внимания Q/K/V/Out,
веса FFN gate/up/down, LM-head) хранится в виде **multi-plane тернарных
значений** `{-1, 0, +1}` с масштабами по группам. В результате файл целиком
обученной модели измеряется в **килобайтах** — а не в гигабайтах.

> **Активации не хранятся и по умолчанию не квантуются.** Промежуточные
> активации (эмбеддинги токенов, скрытые состояния, выходы внимания/FFN)
> вычисляются **во время работы как обычный FP32** и никогда не сохраняются
> в файл модели. Векторы гамм RMSNorm — тоже FP32. Тернарными являются
> только *веса* — именно поэтому файл такой маленький.

> ⚠️ Это образовательный / экспериментальный проект (создан для научной
> статьи). Это не production-инференс-движок.

## 🌍 Главное: LLM в ~28 КБ

Полноценная генеративная языковая модель — токенизатор, веса, всё, что нужно
для общения — умещается в **бинарный файл размером ~29 КБ**. Даже самая
экстремальная конфигурация опускается **ниже 18 КБ**.

| Бенчмарк (один и тот же корпус, русские тексты) | Минимальная | Экстремальная |
|---|---|---|
| Размерность эмбеддингов | 64 | 32 |
| Скрытая размерность FFN | 64 | 32 |
| Головы внимания | 1 | 1 |
| KV-головы | 1 | 1 |
| Слои | 1 | 1 |
| Макс. длина последовательности | 512 | 512 |
| Размер BPE-словаря | 16000 | 16000 |
| Тритовые плоскости | 1 | 1 |
| **Параметры (латентные)** | **106 496** | **49 152** |
| Достигнутый loss обучения | **0.26** | **0.42** |
| **Файл мастер-модели (веса FP32 + токенизатор)** | **420 КБ** | **196 КБ** |
| **Файл тернарной модели (упакованные веса + токенизатор)** | **28,9 КБ** | **17,1 КБ** |
| └ *из них данные токенизатора* | 3,71 КБ | 3,71 КБ |

Иными словами, *собственно веса сети* тернарной модели — всего
**~25 КБ** (минимальная конфигурация) или **~13 КБ** (экстремальная) —
токенизатор занимает четверть файла.

Модель такого размера — это почти целиком заслуга **тернарного формата
квантования**: веса даже «экстремальной» модели, напечатанные на бумаге,
едва заполнят страницу.

## Как достигается размер

### Две модели, один конвейер обучения

| | Мастер-модель (`TernaryTraining`) | Тернарная модель (`TernaryInference`) |
|---|---|---|
| Роль | обучается на CPU | только инференс |
| Веса | FP32 (латентные) | упакованные тернарные `{-1,0,+1}` |
| Файл | `master_model.bin` (большой) | `ternary_model.bin` (крошечный) |
| Назначение | обучение + экспорт | развёртывание / чат |

1. Вы **обучаете** мастер-модель с обучением, учитывающим квантование (QAT):
   на каждом прямом проходе веса FP32 на лету квантуются до тернарных
   (straight-through estimator), так что модель учится весам, переживающим
   агрессивное квантование.
2. Вы **экспортируете** (`SyncToInferenceModel`) → тернарная модель упаковывает
   веса в компактный битовый формат и записывает `ternary_model.bin`.
3. Вы **распространяете только** тернарную модель — её может загрузить и
   использовать для общения небольшая программа инференса, в которой
   **нет ни строчки кода обучения**.

### Что лежит на диске (тернарный формат)

Файл модели хранит **только обученные параметры** — никаких активаций,
никаких вычисленных состояний. Каждый вес — это сумма тернарных слоёв:

```
w ≈ Σₚ scale[p] · t[p],   где t[p] ∈ {−1, 0, +1}
```

- **Триты** упаковываются **по пять на байт** в троичном (base-3) кодировании
  (один трит — это `log₂(3) ≈ 1,585 бита`, значит 5 тритов ≈ 7,9 бит ≈ один
  байт) — никогда не хранятся как обычные байты или float.
- **Масштабы** хранятся в **FP16** (один масштаб на группу из `GroupSize`
  весов, `ScaleMode.PerGroup`).
- **Векторы гамм RMSNorm** (`norm1`, `norm2`, `final_norm`) — их мало, и они
  крошечные — FP32, пренебрежимо малая доля файла.
- `planes = 1` → классический **1.58-bit** (BitNet); `planes = 2` → аналог INT3;
  `planes = 6` → аналог INT6. Больше плоскостей → выше точность, но
  пропорционально больше файл.

Итог: ~13–25 КБ весов для полноценной диалоговой LLM.

## Архитектура Llama (реализована с нуля)

- **RMSNorm** перед вниманием и FFN (с гаммой на каждый блок)
- **Многоголовое внимание с GQA** (grouped-query attention) + **RoPE**
  позиционное кодирование (`theta = 10000`)
- **SwiGLU FFN** (gate × up → down)
- **Pre-norm остаточные блоки** с **привязанными эмбеддингами токенов**
  (LM-head разделяет матрицу эмбеддингов)
- **KV-кэш** при инференсе, **causal-маска** при обучении
- Опциональный экспериментальный `AttentionMode`: `Softmax` (по умолчанию) /
  `TopK` / `Hardmax`

Всё — движок autograd, оптимизатор AdamW, тензорные операции, RoPE,
BPE-токенизатор — написано на C# вручную.

## Структура репозитория

```
├── LLamaTritLLM.sln                  # Решение с обеими программами
├── training/                         # ═══ Программа "TernaryTraining" ═══
│   ├── TernaryTraining.csproj        #   собирает полное приложение для обучения
│   ├── Program.cs                    #   CLI: создать / обучить / дообучить / экспорт / чат
│   ├── core/                         #   общее: конфиг, упаковщик, токенизатор, сериализация
│   ├── ternary/                      #   тернарная модель инференса (модель, блоки, KV-кэш)
│   └── train/                        #   мастер-модель, autograd, AdamW, тренер
└── inference/                        # ═══ Программа "TernaryInference" ═══
    ├── TernaryInference.csproj       #   собирает ТОЛЬКО core + ternary (без кода обучения)
    └── Program.cs                    #   загрузка ternary_model.bin и чат
```

Программа `inference` собирается только из `core/` + `ternary/` — обучающий
стек (`train/`) **никогда не попадает** в развёртываемый бинарник.

```bat
dotnet build LLamaTritLLM.sln
```


## Использование

### 1. Программа обучения — `TernaryTraining.exe`

```bat
cd training\bin\Debug\net8.0
TernaryTraining.exe
```

Интерактивное меню:

| Пункт меню | Действие |
|---|---|
| **Создать модель** | выбрать размерности → сначала обучается BPE-токенизатор на вашем корпусе → модель создана |
| **1. Pretrain** | предобучение языковой модели на `data/pretraining_data.json` |
| **2. Tune** | дообучение под чат на `data/chat_training_data.json` |
| **3. Сохранить** | сохранить веса мастера (`models/master_model.bin`) |
| **5. Экспорт тернарной** | упаковать мастера → `models/ternary_model.bin` |
| **8. Интерактивный чат** | общение с использованием тернарной модели |
| **9. Выход** | — |

Типичный порядок: **создать модель → pretrain → дообучить → сохранить →
перезапустить → загрузить → экспорт → чат**. Значения по умолчанию повторяют
конфигурации из бенчмарка выше (`emb=64, hidden=64, heads=1, kv=1, layers=1,
seq=512, vocab=16000, planes=1`).

Файлы данных (`data/*.json`) ожидаются рядом с исполняемым файлом
(`training\bin\Debug\net8.0\`).

### 2. Программа инференса — `TernaryInference.exe`

```bat
cd inference\bin\Debug\net8.0
TernaryInference.exe models\ternary_model.bin
```

Аргументы командной строки:

| Аргумент | Значение |
|---|---|
| `ternary_model.bin` (позиционный) | путь к файлу тернарной модели |
| `--temp 0.7` | температура сэмплирования (по умолчанию 0.7) |
| `--prompt "текст"` | выполнить один промпт и выйти |
| `--help` | справка |

Без `--prompt` запускается интерактивный чат:
`exit` — выход, `temp N` — изменить температуру.

**Честное замечание:** сеть размером 17–29 КБ — это *очень* скудный мозг.
Не ждите диалогов глубже (намеренно крошечного) обучающего корпуса. В этом
и смысл проекта — протолкнуть **нижнюю границу** того, чем может быть LLM.

## Форматы файлов модели

| Файл | Магия | Содержимое |
|---|---|---|
| `master_model.bin` | `TRAINABLE_LLAMA_WEIGHTS_V1` | конфиг + BPE-токенизатор + дампы FP32-тензоров |
| `ternary_model.bin` | `TERNARY_LLAMA_V1` | конфиг + токенизатор + упакованные тернарные слои + FP16-масштабы |
| упакованные слои | `MPTP_V2` | FP16-масштабы + base-3 упакованные триты (5 тритов/байт) |
| токенизатор | `BPE_COMPACT_V1` | спецтокены + пары merges как varint |
